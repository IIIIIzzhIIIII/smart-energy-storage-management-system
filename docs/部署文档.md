# 光储智慧能源管理平台 部署文档

## 一、环境准备

请提前安装以下软件（版本按建议安装）：

| 软件 | 版本 | 用途 |
|------|------|------|
| JDK | 17（Spring Boot 2.7 支持的 LTS 上限，勿用 25） | 运行后端 |
| Maven | 3.6+（IDEA 内置亦可） | 后端构建 |
| MySQL | 8.0（5.7 兼容） | 数据库 |
| Node.js | 18 LTS | 前端构建 |
| Python | 3.9~3.13 | 预测/调度服务（SARIMA、Copula、DRO） |
| Navicat | 任意 | 数据库管理（可选） |
| IDEA | Community | 运行后端（推荐） |

## 二、初始化数据库

1. 打开 Navicat，连接本机 MySQL（root 用户）。
2. 新建查询窗口，把 `backend/sql/init.sql` 的**全部内容**粘贴进去并执行。
   - 会自动创建数据库 `energy_monitor`、14 张表，以及内置账号和示例数据。
   - 若是在**已有数据库**上升级（不想清空数据），改执行增量脚本：
     - `backend/sql/dispatch_update.sql`（峰平谷、调度指令表）
     - `backend/sql/ev_charging_update.sql`（充电订单表 + 充电桩设备）
3. 确认 `energy_monitor` 库下出现 `sys_user`、`device`、`device_data` 等表。

> 也可命令行执行：`mysql -uroot -p < backend/sql/init.sql`

## 三、配置并启动后端

1. 修改 `backend/src/main/resources/application.yml`：
   ```yaml
   spring:
     datasource:
       url: jdbc:mysql://localhost:3306/energy_monitor?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
       username: root
       password: 你的MySQL密码   # ← 改成你自己的密码
   ```
2. 用 IDEA 打开 `backend` 目录（Open → 选择 backend 文件夹）。
3. 等待 Maven 自动下载依赖。
4. 运行 `EnergyMonitorApplication`（位于 `com.energy` 包下）。
5. 控制台出现「光储智慧调度监控平台 后端启动成功」即成功，后端监听 8082 端口。
   - 启动后系统会每 3 秒自动生成一批模拟数据，告警检测每 5 秒执行一次。

## 四、启动 Python 预测调度服务

预测与调度服务（SARIMA 预测、D-Vine Copula、DRO 鲁棒调度）是独立进程，与后端并列运行（端口 8000），**每次启动系统都需要运行**。

在终端执行：

```bash
cd python-ems
pip install -r requirements.txt   # 首次需安装依赖（建议用清华镜像）
python main.py
```

- 等待输出服务启动信息，服务监听 8000 端口；接口文档：http://localhost:8000/docs
- 后端启动后会自动调用本服务获取 DRO 调度计划（默认每 5 分钟刷新一次）。
- 若本服务未启动，大屏「DRO 调度计划」面板会提示获取失败，其余功能不受影响。

## 五、配置并启动前端

在 VS Code 打开终端，执行：

```bash
cd frontend
npm install
npm run dev
```

- 等待输出 `Local: http://localhost:5173`
- 浏览器打开 http://localhost:5173

## 七、常见问题排查

**1. 后端启动报数据库连接失败**
- 检查 MySQL 是否启动、`application.yml` 密码是否正确、是否已执行 `init.sql`。

**2. 前端页面能打开但登录报 401 / 网络错误**
- 确认后端 8082 已启动；
- 前端通过 Vite 代理访问后端，确认 `vite.config.js` 中代理 target 为 `http://localhost:8082`。

**3. 大屏没有实时数据**
- 确认数据库 `device` 表有设备；
- 后端启动一段时间后（3秒一批），刷新页面或等 3 秒。

**4. 端口冲突**
- 后端 8082 被占用：改 `application.yml` 的 `server.port`，同时改前端 `vite.config.js` 代理 target；
- 前端 5173 被占用：改 `vite.config.js` 的 `server.port`。

**5. 大屏「DRO 调度计划」显示获取失败**
- 确认 Python 服务已启动（`cd python-ems && python main.py`）；
- 确认 `application.yml` 中 `energy.python.base-url` 为 `http://localhost:8000`；
- 若 8000 端口被占用，修改 `main.py` 的启动端口，并同步修改 `application.yml` 的 `base-url`。

**6. IDEA 报「无法编译为 JVM 目标 25 配置的模块 'energy-monitor'：指定的回退 SDK 版本 8 不支持所需 jvm 目标 25」**
- 原因：模块编译目标（`pom.xml` 的 `java.version`）高于 IDEA 项目 SDK 的能力，IDEA 会退回到机器上的回退 JDK（本机为 Java 8）编译，于是失败；同时 Spring Boot 2.7 也无法读取 Java 25 的 class 文件（major 69）。
- 处置：`backend/pom.xml` 的 `java.version` 固定为 `17`（Spring Boot 2.7 支持的 LTS 上限），不要改成 25；
- 检查 IDEA → File → Project Structure → Project SDK 为 JDK 17 或 21（不要选 Java 8）；
- 改过 `pom.xml` 后，在 Maven 工具窗口点「Reload All Maven Projects」（⟳）重新导入；
- 命令行打包需先指向 JDK 17+：
  ```powershell
  $env:JAVA_HOME="<你的 JDK 17 安装目录>"
  mvn clean package -DskipTests
  ```

## 八、打包部署（可选）

**后端打 jar 包：**
```bash
cd backend
mvn clean package -DskipTests
java -jar target/energy-monitor-1.0.0.jar
```

**前端打包：**
```bash
cd frontend
npm run build
```
生成的 `dist` 目录可部署到 Nginx，并配置 `/api` 反向代理到 8082、`/ws` 代理到后端 WebSocket。

**Python 服务部署：**
```bash
cd python-ems
pip install -r requirements.txt
nohup python main.py &   # Linux 后台运行；生产环境建议用 systemd 或 Docker 常驻
```
